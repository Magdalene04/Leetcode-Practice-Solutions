# 42. Trapping Rain Water

- **Problem Link:** [LeetCode - 42. Trapping Rain Water](https://leetcode.com/problems/trapping-rain-water/)
- **Difficulty:** 🔴 Hard
- **Topics:** Array, Two Pointers, Dynamic Programming, Stack, Monotonic Stack

---

## 📝 Problem Statement

Given `n` non-negative integers representing an elevation map where the width of each bar is `1`, compute how much water it can trap after raining.

---

## 💻 Solution

```python
class Solution:
    def trap (self, height: List[int] ) -> int:
       left_wall = right_wall = 0
       n = len(height)
       max_left = 0*n
       max_right = 0*n
       for i in range (n):
           j = -i -1
           max_left[i] = left_wall
           max_right[j] = right_wall
           left_wall = max(left_wall, height[i])
           right_wall = max(right_wall, height[j])
       sum = 0
       for i in range(n):
           potential_water = min(max_left[i],max_right[i])
           sum = sum + max(0, potential_water-height[i])
       return sum
```

## ⏱️ Complexity Analysis

* **Time Complexity:** $O(n)$  
  We make two linear passes over the array of length $n$: the first pass populates `max_left` and `max_right` simultaneously, and the second pass computes the trapped water at each index.

* **Space Complexity:** $O(n)$  
  We allocate two auxiliary arrays (`max_left` and `max_right`), each of size $n$, to store the boundary maximums for every element.

---

## 💡 Key Takeaways & Intuition

* **Water Bound by Minimum Heights:**  
  I realized that the water level above any index $i$ depends strictly on the shorter of the highest walls to its left and right ($\min(\text{max\_left}, \text{max\_right}) - \text{height}[i]$).

* **Precomputing Subproblems (Dynamic Programming):**  
  Instead of scanning left and right for every index—which would take $O(n^2)$ time—I used DP tables (`max_left` and `max_right`) to precompute and memoize the running maximum heights from both directions in a single pass.

* **Python List Initialization & Naming:**  
  I noted two important Python details: using `[0] * n` instead of `0 * n` to initialize lists of size $n$, and avoiding shadowing Python's built-in `sum()` function by using `total_water` instead.
