# 42. Trapping Rain Water

- **Problem Link:** [LeetCode - 42. Trapping Rain Water](https://leetcode.com/problems/trapping-rain-water/)
- **Difficulty:** 🔴 Hard
- **Topics:** Array, Two Pointers, Dynamic Programming, Stack, Monotonic Stack

---

## 📝 Problem Statement

Given `n` non-negative integers representing an elevation map where the width of each bar is `1`, compute how much water it can trap after raining.

---

## 💻 Solution

```python
class Solution:
    def trap(self, height: List[int]) -> int:
        left, right = 0, len(height) - 1
        left_wall = right_wall = 0
        total_water = 0

        while left < right:
            if height[left] < height[right]:
                if height[left] >= left_wall:
                    left_wall = height[left]
                else:
                    total_water += left_wall - height[left]
                left += 1
            else:
                if height[right] >= right_wall:
                    right_wall = height[right]
                else:
                    total_water += right_wall - height[right]
                right -= 1

        return total_water
```

## ⏱️ Complexity Analysis

* **Time Complexity:** $O(n)$  
  We process each elevation bar in the array of length $n$ at most once using two pointers moving towards each other.

* **Space Complexity:** $O(1)$  
  By maintaining running tracking variables (`left_max` and `right_max`), we avoid storing precomputed prefix/suffix max arrays, achieving constant auxiliary space.

---

## 💡 Key Takeaways & Intuition

* **Water Bound by the Shortest Wall:**  
  I realized that the water level above any specific bar $i$ is capped by the minimum of the highest wall to its left and the highest wall to its right ($\min(\text{left\_max}, \text{right\_max}) - \text{height}[i]$).

* **Decisive Pointer Movement:**  
  I learned that I don't need to know *both* maximum heights exactly for every single bar. By comparing `height[left]` and `height[right]`:
  * If `height[left] < height[right]`, I know for sure that `left_max` is the true limiting factor for the `left` position, so I can calculate water trapped at `left` and increment `left`.
  * Otherwise, `right_max` is guaranteed to be the bottleneck, so I calculate trapped water at `right` and decrement `right`.

* **Upgrading from $O(n)$ Space to $O(1)$:**  
  While the standard Dynamic Programming approach uses two $O(n)$ prefix/suffix arrays to record max heights, using two pointers lets me track these maximums dynamically on the fly, optimizing space complexity down to $O(1)$.
