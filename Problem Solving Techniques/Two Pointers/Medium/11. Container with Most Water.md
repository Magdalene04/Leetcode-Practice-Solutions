# 11. Container With Most Water

- **Problem Link:** [LeetCode - 11. Container With Most Water](https://leetcode.com/problems/container-with-most-water/)
- **Difficulty:** 🟡 Medium
- **Topics:** Array, Two Pointers, Greedy

---

## 📝 Problem Statement

You are given an integer array `height` of length `n`. There are `n` vertical lines drawn such that the two endpoints of the $i^{\text{th}}$ line are `(i, 0)` and `(i, height[i])`.

Find two lines that together with the x-axis form a container, such that the container contains the most water.

Return *the maximum amount of water a container can store*.

**Notice** that you may not slant the container.

---

## 💻 Solution

```python
class Solution:
    def maxArea (self, height: List[int]) -> int:
        left = 0
        right = len(height) - 1
        max_area = 0
        while left < right:
            w = right - left
            h = min(height[left],height[right])
            a = w * h
            max_area = max(max_area, a)
            if height[left] < height[right]:
                 left = left + 1
            else:
                 right = right - 1
        return max_area
```

## ⏱️ Complexity Analysis

* **Time Complexity:** $O(n)$  
  We evaluate the array of length $n$ using two pointers. Each step eliminates one vertical line by advancing either the left or right pointer, scanning the array in a single pass.

* **Space Complexity:** $O(1)$  
  Only a few primitive variables (`left`, `right`, `max_area`) are stored, requiring constant additional memory.

---

## 💡 Key Takeaways & Intuition

* **Identifying the Limiting Factor:**  
  I realized that the area is bounded by the shorter line ($\text{width} \times \min(\text{height}[left], \text{height}[right])$). The shorter wall is always the bottleneck determining maximum height.

* **Greedy Two-Pointer Strategy:**  
  I started with the maximum possible width by setting `left = 0` and `right = len(height) - 1`. To find a larger area as the width shrinks, I must move the pointer pointing to the **shorter line**. Moving the taller line can only decrease width without improving height, making a larger area mathematically impossible.

* **Optimizing from $O(n^2)$ to $O(n)$:**  
  By eliminating the shorter wall at each step, I avoided checking all $O(n^2)$ line combinations and solved the problem in a single linear pass.
