# 125. Valid Palindrome

- **Problem Link:** [LeetCode - 125. Valid Palindrome](https://leetcode.com/problems/valid-palindrome/)
- **Difficulty:** 🟢 Easy
- **Topics:** Two Pointers, String

---

## 📝 Problem Statement

A phrase is a **palindrome** if, after converting all uppercase letters into lowercase letters and removing all non-alphanumeric characters, it reads the same forward and backward. Alphanumeric characters include letters and numbers.

Given a string `s`, return `true` *if it is a palindrome, or* `false` *otherwise*.

---

## 💻 Solution

```python
class Solution:
     def isPalindrome(self, s: str) -> bool:
          left = 0
          right = len(s) - 1
          while left < right:
               if not s[left].isalnum():
                    left = left + 1
                    continue
               if not s[right].isalnum():
                    right = right - 1
                    continue
               if s[left].lower() != s[right].lower():
                    return False
               left = left + 1
               right = right - 1
         return True
```

## ⏱️ Complexity Analysis

* **Time Complexity:** $O(n)$  
  We traverse the string of length $n$ using two pointers, skipping non-alphanumeric characters and checking each valid character at most once.

* **Space Complexity:** $O(1)$  
  By inspecting characters directly on the input string using pointers, we avoid instantiating a new cleaned string, maintaining constant $O(1)$ extra space.

---

## 💡 Key Takeaways & Intuition

* **In-Place Processing Saves Space:**  
  I learned that instead of allocating a new filtered string with `isalnum()` and `.lower()` (which would cost $O(n)$ extra space), I can evaluate the string directly in-place using two pointers to keep space strictly $O(1)$.

* **Skipping Invalid Characters On-The-Fly:**  
  I set `left = 0` and `right = len(s) - 1`. While moving inward, I used inner `while` loops with `isalnum()` to skip spaces and special characters until both pointers landed on valid letters or numbers.

* **Case-Insensitive Comparison:**  
  I observed that calling `.lower()` on the flying character comparisons (`s[left].lower() != s[right].lower()`) handles case mixing smoothly without needing pre-processing on the whole string.
